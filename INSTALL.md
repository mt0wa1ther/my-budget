# Финансы: адаптивный интерфейс и синхронизация, протокол 2

## Что входит
- index.html — актуальная версия с белой/тёмной темами, без сторонних внедрённых подключений.
- server.js — Node.js-сервер без сторонних npm-зависимостей.
- SHA256SUMS.txt — контрольные суммы файлов.

package.json не требуется. Команда запуска: node server.js. Используйте поддерживаемую версию Node.js (рекомендуется 18+).

## Перед обновлением
1. На каждом устройстве с важными несинхронизированными изменениями экспортируйте резервную копию из приложения.
2. Сохраните текущие index.html, server.js и ВСЮ существующую папку data.
3. Не очищайте браузерное хранилище и не удаляйте папку data.
4. Обновлять нужно и GitHub-репозиторий, и опубликованный сервер.

## Установка
1. Поместите index.html в существующий корень сайта. В вашем случае это /var/www/finance/index.html.
2. Замените текущий запускаемый server.js новым. Не запускайте второй сервер параллельно на том же порту.
3. Сохраните текущую папку данных. По умолчанию DATA_DIR = папка data рядом с server.js, PUBLIC_DIR = public рядом с server.js, PORT = 9090 (как в присланном сервере).
4. Если текущая конфигурация отличается, задайте переменные среды у существующего процесса/службы:
   PUBLIC_DIR=/var/www/finance
   DATA_DIR=ПОЛНЫЙ_ПУТЬ_К_СУЩЕСТВУЮЩЕЙ_ПАПКЕ_DATA
   PORT=9090
   Путь DATA_DIR нужно узнать из текущего размещения старого server.js, а не создавать пустую папку наугад.
5. Перезапустите ТУ ЖЕ службу/процесс, который уже обслуживает ваш backend (systemd, PM2 и т.п.).
   Точная команда перезапуска зависит от существующего способа запуска. Не выполняйте npm install: зависимостей нет.
6. Проверьте backend: curl --fail http://127.0.0.1:9090/api/health
   Ожидается {"ok":true,"protocol":2}.
7. Проверьте публичный маршрут /api/health через ваш сайт. Если 404, прокси должен передавать /api/ на backend.
8. После обновления оба устройства должны перезагрузить страницу. Старые клиенты отклоняются при записи (HTTP 428), чтобы не затереть новые данные.
9. Введите одинаковый код комнаты из 6 латинских букв/цифр на всех устройствах.

## Компоновки
- Телефон: мобильные карточки, нижняя навигация.
- Планшет: более широкая двухколоночная раскладка.
- От 1024 CSS-пикселей: боковая навигация и широкий дашборд.
- Это адаптация по размеру окна, а не определение модели устройства.
- Светлая/тёмная темы и автоматическое переключение 07:00/20:00 сохранены, по местному времени устройства.

## Синхронизация
- Одна комната = один общий бюджет на устройствах.
- При активной вкладке запросы идут примерно каждые 4 секунды, строго последовательно в одной вкладке.
- При возврате на страницу и восстановлении сети выполняется проверка.
- Изменённые данные сразу сохраняются локально. При временном отключении сети сохраняется очередь.
- Очередь хранится в localStorage и повторяется после возврата связи/повторного открытия страницы с интернетом.
- Это НЕ полноценный офлайн-PWA: холодное открытие сайта без сети не реализовано. Требуются HTTPS и отдельный Service Worker для этого сценария.
- Независимые добавления трат/шаблонов с разными ID объединяются. Категории/подкатегории сопоставляются по имени.
- Одновременные изменения одного поля (например, одной суммы дохода) не суммируются наугад: появляется конфликт.
- При конфликте сохраните свою копию, затем выберите серверную версию или осознанную замену серверной своей.
- Старые записи без уникальных ID могут вызвать конфликт вместо автоматического объединения — данные не затираются молча.
- Текущий выбранный месяц, оформление и режим темы локальны; содержимое бюджета общее.
- Фоновая работа закрытого браузера не обещается; синхронизация возобновляется при открытии.

## Миграция хранения и ограничения
Существующие data/КОД.json читаются автоматически. При первом успешном сохранении формат становится:
{_finance:2, revision:..., data:..., receipts:[...]}
Не редактируйте эти файлы вручную. Старый server.js не умеет читать новый формат! Для отката восстанавливайте согласованную резервную копию сервера и папки data.
Сервер рассчитан на ОДИН процесс Node.js и локальную файловую систему. Не включайте PM2 cluster / несколько workers / несколько контейнеров с общей папкой данных. Для этого нужна БД и транзакции.
Сохранение использует проверку версии и атомарное переименование файла. Повтор запроса с тем же ID не дублирует сохранение; хранится 256 последних ID.
Максимальный JSON-запрос: 4 МиБ.

## Безопасность
Прежняя модель доступа по коду комнаты сохранена. Это не полноценная регистрация, пароль или разграничение прав.
Для финансовых данных в публичной сети необходим HTTPS. Сейчас ваш адрес использует HTTP.
Для более строгой защиты нужны учётные записи, авторизация, ограничение перебора и резервное копирование на стороне сервера.
Обновление не меняет настройки HTTPS/прокси автоматически.
Не публикуйте папку data в GitHub. Сервер блокирует её выдачу даже если она расположена внутри PUBLIC_DIR.
При обновлениях используйте архив/исходники, а не «Сохранить страницу» из браузера. Проверяйте отсутствие посторонних script/link в коммите.

## Проверено
- Синтаксис всех встроенных JS и server.js.
- Мобильная ширина 360/390, планшет 768, ПК 1024/1440, все разделы: без горизонтального переполнения.
- Мобильное и десктопное окно в независимых браузерных контекстах на реальном локальном Node-сервере.
- Одновременное добавление двух разных трат: обе сохраняются и видны на обоих устройствах.
- Отключение сети, локальная очередь и восстановление синхронизации.
- Одновременное изменение одной суммы: отображается конфликт, чужая версия не затирается.
- Повтор запроса с тем же ID, отказ устаревшему клиенту, чтение старой комнаты.
- Ручные белая/тёмная темы.
Реальные iPhone/Safari, ваша служба Node/прокси и production-сеть здесь не проверены.
